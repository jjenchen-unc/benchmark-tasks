S1 swing handle: Arena preparation

This is one historical development unit, not five submission tasks. The representative remains native **SH-T1, fixed physical case 42**: open box 1 past 60 degrees using its handle and leave every part of that box untouched by both arms for 20 seconds. A_box3, SH-T2 and SH-T4 retain their open–close–compress–stow goals; SH-T3 retains its changed mechanism parameters. `S1_TARGET` selects their assets/scorer for diagnostics; the robot reference implements SH-T1. Nothing here establishes submission readiness.

From this directory, with the pinned Arena/Inspect runtime already available:

```bash
python run.py --mode foundation --out /absolute/writable/foundation-output
python run.py --mode negatives --out /absolute/writable/evaluator-negatives-output
python run.py --mode reference --out /absolute/writable/robot-reference-output
```

Run physics only in the root supervisor's allocated GPU job. Foundation uses CPU PhysX with allocated GPU RTX cameras; it is not a claim that S1 GPU PhysX is defective. The optional `--legacy-rtx-override` adds only the explicit process-local AppLauncher driver check argument. There are no model/API calls. `run.py` saves raw substep measurements, errors and partial results. Foundation checks actual drive ceilings, joint/body/contact resolution, three RGB streams, the 20 Hz/1 ms clock, arbitrary harness seed routing, reset history and step-after-termination refusal. Evaluator placement in `--mode negatives` is explicitly isolated from the genuine robot reference. Evaluator results cannot count as demonstrations.

The portable task entry is `task.py` (`SCENE=station`, `SCORE_OVER=end`). Actual Inspect/Dream integration, CLI evaluation and final media are pending. A full trial permits 4,198 genuine 14D absolute joint/gripper controls at 20 Hz, 209.9 simulation seconds; wall runtime is unmeasured. The reference nominally lasts 56.5 s including a 21 s hands-off attempt. It returns six joint targets and one public mean-jaw fraction per arm, with rate limits; every task-object change during that route must arise from robot contacts. It reads observed robot joints and privileged measured wrist forces plus the fixed mechanism design. It cannot write object poses, task joints, forces, latch/score/history fields. YAM arm limits are TOTAL 27/7 Nm including gravity, using a task-local copy of the verified B5/D3 implicit-drive gravity-offset adapter. Actual `root_view.get_dof_max_forces` must confirm these and the **50 N** finger ceiling. Native Robotiq 235 N capacity is not carried over; grip and full-goal feasibility at YAM capacity remain unproved.

All task geometry receives the same rigid translation (+0.25, 0, -0.0525) m. Robot bases stay at the actual station positions (0, ±0.305, 0.75) m. The tabletop is z=0.7475 m. There is no object resizing or fixing of a source free body. The source fixed shells are represented by concealed underside bench bolting, not by an unsupported freestanding interpretation. Clearance to arms, station fixtures and other boxes remains unverified. No clearance claim follows from IK.

Physical inventory and layout (source estimates; all lengths metres):

- Three rigid enclosures, nominal outside 0.20 × 0.22 × 0.112; shell wall/bottom thickness 0.01. Steel-like painted rigid shells, bench bolted; centres (0.25, -0.32/-0.08/0.16, 0.7975). Dynamic shell mass is irrelevant to the fixed-world source; numerical fixed-link mass is 0.001 kg in USD. The invisible fixed support also has 0.001 kg, outside the movable parts.
- Three steel-like lids, 0.20 × 0.20 × 0.012, 0.5 kg plate mass each (fixed type-B/C red caps add 0.01 kg to their lid body); hinge frames (0.15, box_y, 0.8595), about local -Y, initially -0.020 rad. Every body, local shape transform, diagonal inertia, principal axis, mass and joint range is in `fixture.json`. USD files are compiled primitives, with no meshes or textures.
- Each lid carries a 0.05 kg cylindrical handle hub (radius 0.011, height 0.028), a 0.12 kg black rigid bar (0.022 × 0.125 × 0.014), and a 0.01 kg pivot (radius 0.009, length 0.024). Shaft lid-local (0.165, 0.070, 0); grip point 0.105 along the bar. The 0.012-diameter red cap stands 0.014 above the lid. Type-A cap has mass 0.01 kg and 3 mm travel; type-C push slide has 5 mm travel and numerical/physical moving mass 0.01 kg. Exact visual gasket/housing/inside primitives are also enumerated in JSON.
- Rubber-like gasket: nominal 4 mm far-edge compression; equivalent spring stiffnesses for boxes 1/2/3 are approximately 31528/66628/33026 N/m. Rigid-contact Coulomb friction is 1.0 except the lever bar 1.1; restitution zero. Estimated materials and rigid contact do not model plastic failure, flexible skins, rod bending or seals as a continuum.
- Standard station table, two unmodified YAM robot assets, camera stand, lamp, top camera and wrist cameras come from the pinned SDK. They are runtime dependencies, not bundled Panda/Robotiq assets. Station geometry and camera calibration come from that SDK, not invented new support dimensions.

Reset restores default roots and all eleven movable task joints (four on the single-box SH-T4), velocities and passive mechanism memory; all lid hinges begin -0.020 rad and all other coordinates zero. It then performs the real SDK settling sequence and starts a fresh task clock/history. `object_jitter=0` is required. Different Inspect-derived episode IDs/seeds are accepted and mean the same declared physical case; there is no seed-42-only rejection. Fixed-case mechanism parameters are not added to public robot observations.

Scoring is numeric and matches the native tiers. SH-T1/SH-T3: 1.0 for final >60° opening held 20 s hands-off; 0.5 for >60° at the end without the hold; 0.25 for released lock and final >10° opening; otherwise 0. Open–close variants: no credit until an actual >60° opening occurred; then 0.25 while not closed to 10 mm, 0.5 for final gap <10 mm, 0.75 when cam-engaged, gap <1 mm and swing ≤5.5°; full score additionally requires lever <4°, type-A pop catch re-engaged, and 20 s hands-off. Gap is 0.20 × lid_angle + 0.004 m as in the source. Every link of either robot contacting any part of the target, including its fixed shell, resets hold. Any raw untared wrist force >80 N continuously for 0.1 s permanently zeroes the trial. Reference tool guards use raw untared force at 30 N, or 45 N during handle lifting, for 0.1 s. Public taring cannot erase either guard. Native tasks do not define a separate free-object drop tier; their movable parts remain joint connected. Time exhaustion retains the final numeric tier subject to the sticky safety veto.

`rubric.py` reports measured candidate scores separately. **Official task credit stays zero while any of joint state, clock, contact, wrist force, mechanism or total motor channels is unverified.** Static/native claims do not populate `VERIFIED_CHANNELS`. Actual calibrated evidence and a source-bound root decision are needed before changing that gate.

Fidelity and deviations: source conditional equalities become passive finite-stiffness penalty cams/catches evaluated every 1 ms. Engaged cam reactions are balanced between lid and swing coordinates; gasket forces store/release spring energy. Task targets and forces are environment constitutive laws, not policy commands. Current stiffness/damping need actual calibration; finite compliance changes transient and possibly static gasket compression. Source constant hinge friction is authored with PhysX joint-axis static/dynamic friction effort. Native task-to-task masks suppress mutual collisions, retained through explicit body pair filters; robot-to-task contacts remain enabled. These source approximations must not be mistaken for detailed multipoint rods. Full hold, release, latch integrity, sensor response, stability and robot clearance are not yet validated.

The revised reference attempts a 65° handle lift and +X retreat instead of the native robot's 45° lift followed by edge push to 72°. The scored >60° condition is unchanged; this is robot motion adaptation, not reduced task difficulty. Both source geometry and the original failed native-style plan are preserved in readiness artifacts. All sampled revised reference waypoints have SDK IK solutions; no dynamics, force or swept-clearance success follows.

`build_usd.py` regenerates USD using pxr only and local JSON. Arena runtime does not import MuJoCo or the historical workspace. Exact copied source was actually executed before cold SDK task loading; source receipts, differential checks, failed plans, board primary records and provenance live in the matching readiness directory. `task.draft.json` is deliberately not final `task.json`. Required remaining work: actual foundation/known-load/contact/latch negatives, physical reference/full goal, independent replay, actual Dream-1, media, and refreshed primary board/ownership comparison before publication. No blanket FEM, hardware campaign or multiseed requirement is asserted.
