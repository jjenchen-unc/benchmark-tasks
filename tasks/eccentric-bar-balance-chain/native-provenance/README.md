# offset stack

**Independent development package; not a submission-ready task.**

This folder contains its own one-bench scene/support/assets and native runtime. Copy the whole folder anywhere, including `/tmp`, and run it with Python 3.10+ and the pinned dependencies. No sibling Robocurve/TinkerBench project is imported. Panda robot meshes come from the pinned robosuite package.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
./run.sh
./run.sh --list-variants
./run.sh build --target stack_ABC --setting S --dry-run
./run.sh reset
./run.sh step --steps 1
./run.sh reference --output artifacts/reference.json
./run.sh render --output artifacts/setup.ppm
```

To reuse an already prepared environment after copying this folder:

```bash
ROBOCURVE_NATIVE_PYTHON=/absolute/path/to/prepared/bin/python ./run.sh build
```

Default: `build`, target `stack_ABC`, setting `S`, seed `42`. All goal/setting overrides must belong to candidate.json. Module/root overrides are rejected. Native reference controls are privileged demonstrations, not agent evaluations. The public pose controller and Inspect adapter have smoke/API checks, but no goal has been demonstrated solved through that public pose controller or a model run by this packaging step. Source-privileged reference success does not establish public-controller or model solvability. Reference caches may be regenerated by the source code. Physics steps differ from agent ticks. The runtime reports binary source success with damage and terminal checks; partial credit is not fabricated.

The source-native dual-Panda embodiment, including its source-specific Franka/Robotiq hands, is retained. YAM/Dream conversion is optional. A candidate may be submission-blocked while its variants remain testable.

Optional SDK dependencies:

```bash
.venv/bin/python -m pip install -r requirements-sdk.txt
PYTHONPATH="$PWD/runtime" .venv/bin/python -m robocurve_native.inspect_adapter --help
```

The included Inspect adapter exposes two seven-DOF Panda arms with a 14-value absolute end-effector-pose/jaw action space. It is incompatible with the six-DOF YAM Dream interface. Creating an SDK embodiment/task must use a listed candidate goal/setting from candidate.json and the package-local scene path. No model is called by native build/reference/render or by SDK help.

## Evidence and remaining work

candidate.json preserves exact variant instructions, priority and board exclusions. task-draft.json is explicitly unfinished metadata: it contains no media ID, model score, accepted status or submission task.json. Each candidate needs current board/benchmark distinctness review, an externally measurable numeric scorer with partial-credit/error cases, declared fidelity and reproducible setup, a successful demo and a working agent evaluation route. Disclosed estimates are allowed; new physical calibration is not a universal prerequisite.

manifest.json hashes all packaged files except itself and records source runtime/scene fingerprints. package_fingerprint is computed from its canonical file records. Hash equality can link external evidence to identical inputs; it does not establish an isolated reference rerun. One bench per process prevents collisions among source helper module names.

These commands never submit a PR, upload media or request a compute job. Follow the project/cluster allocation policy when running simulation.

## Wave-13 additions (development evidence only)

**Partial credit (evaluator only):** `scoring/partial_credit.py` is loaded by `runtime/robocurve_native/task.py` and reported in `status()` as `score` (with `binary_source_score` and `partial_credit` detail). The frozen scene predicate is unchanged. Stage k = the first k bars of the required order each touch only the item directly below (support or previous bar) and the next stage bar, are level within 3.4 deg, headed along X within 10 deg and still; any robot contact with any bar resets every stage. Score = k/3 for the highest stage that has held continuously for 20 s at episode end, else 0. A bar outside the stage touching the stage (leaning/bracing), table contact, wrong order, holding a bar, or a hold shorter than 20 s all give no credit for the affected stages. 1.0 is asserted equal to source success (`score_consistent_with_source`). External measurement: order by colour, contact by photo/feeler gauge, level by inclinometer, heading by protractor, stillness/20 s timer by video. Note: the source "still" test is the norm of the bar's 6-dof velocity (m/s and rad/s mixed) below 0.025, slightly stricter than the text's "25 mm/s".

**Public scripted demo:** `demo/public_stack.py --target stack_ABC --variant full --out DIR` (variants: two_bar, one_bar, wrong_order, hold_on, truncate, blind_centre for negatives/diagnostics). It uses the declared fixed layout (bar centres x=0, y=-0.30/-0.19/-0.08 m, z=0.825 m; support centre (0, 0.18), top 0.960 m or 0.9524 m for the riser) and the tared wrist force/torque to identify each bar's hidden COM in-task (offset = -tau_y/F_z while lifted at its middle). It drives only the public 20 Hz pose tools (8 mm/tick, joint torque limits, 30 N guard, 80 N/0.1 s abort, 1896-tick budget). It is a scripted demo, not a model run, and the embodiment is native dual Panda (not YAM/Dream-1).
